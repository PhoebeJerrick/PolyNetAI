背景补充：
该数据流是 Polymarket 市场上 BTC 5分钟周期猜涨跌的完整数据流。我的核心诉求是通过大量数据挖掘可用的因子与最终获胜方向的相关性。特别地，我需要统计每个5分钟周期内某个特定时间区间（例如周期开始后的前2分钟、最后3分钟、或某个自定义偏移区间）的量价指标（如成交量、成交均价、价差等），并分析这些指标与最终获胜方向的相关性及条件占比。因此，脚本需支持灵活配置每个周期内的时间子区间用于因子计算。

请帮我开发一个针对路径 ../Input/5m-RawData 下原始数据流的万能统计脚本，脚本需通过 record.sh 一条指令启动，并支持通过配置文件 batch.conf 进行灵活配置。原始数据为 JSON 格式，每行一条记录，示例数据如下：

json
{"market_id": "btc-up-or-down-5m", "cycle_id": "btc-updown-5m-1774255200", "timestamp": "2026-03-23T08:40:27.135000", "price": 0.5, "shares": 4.0, "outcome": "up", "action": "buy", "source": "polymarket_ws", "metadata": {...}}
{"market_id": "btc-up-or-down-5m", "cycle_id": "btc-updown-5m-1774255200", "timestamp": "2026-03-23T08:40:27.235000", "price": 0.49, "shares": 17.28, "outcome": "up", "action": "sell", "source": "polymarket_ws", "metadata": {...}}
每条记录包含字段：cycle_id（5分钟周期标识）、timestamp、price（交易价格）、shares（交易份额）、outcome（“up”或“down”）、action（“buy”或“sell”）。脚本需要按 cycle_id 分组处理每个5分钟周期内的所有交易。

一、脚本启动方式
执行 ./record.sh 即可启动脚本，脚本内部自动读取 batch.conf 配置文件并运行统计任务。

若配置文件缺失，则使用默认配置（如全量数据、输出基本统计量）。

二、配置文件 batch.conf 格式
配置文件采用键值对格式（支持 key=value 或 JSON），需包含以下可配置项：

1. 全局时间区间筛选（可选）
global_start_time：全局起始时间（ISO8601格式），用于限定分析的数据范围。

global_end_time：全局结束时间。

2. 每个周期内的子时间区间配置（核心新增）
用于限定计算因子时仅使用该周期内的部分交易记录。支持以下配置方式：

time_window_mode：子区间定义方式，可选值：

full_cycle（默认）：使用整个5分钟周期的所有交易。

relative_start：从周期开始后的第 X 秒到第 Y 秒。例如 window_start_sec=0, window_end_sec=120 表示前2分钟。

relative_end：从周期结束前的第 X 秒到结束。例如 window_end_sec=0, window_start_sec=-180 表示最后3分钟。

absolute_time：使用绝对时间偏移，例如 window_start_offset="0s", window_end_offset="2m"。

percentage：按周期时长比例，例如 window_start_pct=0, window_end_pct=0.4 表示前40%的时间段。

具体参数示例：

text
time_window_mode = relative_start
window_start_sec = 0
window_end_sec = 120   # 每个周期内仅使用前120秒的交易数据
或

text
time_window_mode = relative_end
window_start_sec = -180   # 从结束前180秒开始
window_end_sec = 0        # 到周期结束
说明：脚本需根据每个 cycle_id 内交易的时间戳，自动计算该周期的起止时间（该周期第一条和最后一条交易的时间戳，或从 cycle_id 中解析时间戳）。只筛选落在子区间内的交易用于后续因子计算。

3. 基础统计指标（针对每个 cycle_id 的选定子区间）
统计指标基于子区间内的交易计算：

up_volume：子区间内 outcome="up" 的 shares 绝对值之和。

down_volume：子区间内 outcome="down" 的 shares 绝对值之和。

up_avg_price：加权平均价格 = sum(price * shares) / sum(shares)，仅计算子区间内 outcome="up" 的交易。

down_avg_price：同理。

delta_avg_price = |up_avg_price - down_avg_price|。

可选：up_vwap、down_vwap、up_trade_count、down_trade_count 等。

4. 最终获胜结果的定义
该定义基于整个周期（而非子区间）的最终结果。支持以下规则：

win_rule：支持以下模式之一：

last_price：取该周期内最后一条交易（按时间戳）的 price，若 price > 0.5 则 up 获胜，否则 down 获胜。

threshold：用户自定义阈值和方向，如 win_threshold=0.5, win_direction=up。

external_file：从外部文件（如 results.csv）中读取每个 cycle_id 的获胜结果。

script：用户提供的判断脚本。

5. 因子与获胜结果的相关性分析
correlation_var：指定自变量（必须是前面计算的某个指标，如 delta_avg_price、up_volume 等）。

correlation_method：可选 pearson 或 spearman，默认 pearson。

输出相关系数及 p-value（若可能）。

6. 条件占比统计（支持多个条件，可组合）
conditions：一个列表，每个条件包含：

filter：筛选出符合条件的周期（条件表达式可引用子区间内计算的因子，如 up_volume > 300 and delta_avg_price > 0.1）。

group：要计算占比的分组（如 outcome_win 表示该周期最终获胜；outcome_win and outcome='up' 表示最终 up 获胜）。

输出该条件下满足 group 的周期数占总周期数的比例。

7. 开盘价格相关统计（同样支持子区间）
open_price_rule：定义每个周期的开盘价（默认取该周期内第一条交易的 price）。注意：可配置是否限制在子区间内（如 open_price_in_window = true 则只取子区间内的第一条交易作为“开盘价”）。

可配置条件如：open_price_condition = "up_open > 0.45" 并统计 win_ratio。

8. 输出配置
output_format：支持 table、csv、json。

output_path：输出文件路径。

output_columns：指定输出哪些列（如 cycle_id, window_up_volume, window_delta_avg_price, winner）。

支持输出子区间参数作为列名（例如 window_start_sec, window_end_sec）。

三、脚本功能细节要求
数据读取：递归读取 ../Input/5m-RawData 下所有 .json 或 .jsonl 文件。

分组处理：按 cycle_id 分组，对每个组内的交易按 timestamp 排序，并确定该周期的实际起止时间（最早和最晚时间戳）。

子区间筛选：根据配置的 time_window_mode 计算出每个周期的子区间起止时间戳，只保留该区间内的交易用于因子计算。若子区间内无交易，则该周期跳过或标记为缺失（可配置）。

性能考虑：支持流式处理，按 cycle_id 缓存一个周期内的所有交易（因为需要先知道整个周期的时间范围才能划分子区间），但可限制内存中同时持有的周期数量。

错误处理：对于缺失字段、无效时间戳、子区间无数据等异常，记录警告日志并跳过该周期。

扩展性：支持用户通过 custom_metrics 添加自定义表达式指标，例如 {"up_vwap_window": "sum(price*shares)/sum(shares) filter outcome='up' and time_in_window"}。

帮助信息：执行 record.sh --help 时打印详细配置说明，包括子区间配置示例。
