**文件位置**：[docs/strategy_spec_enhanced.md](strategy_spec_enhanced.md)

**适用场景**：
- ✅ 需要完整的策略逻辑参考
- ✅ 团队成员查阅策略细节
- ✅ 新成员快速上手
- ✅ 调试时逐行对照代码
- ✅ 参数化配置的完整说明

**内容结构**：
```
├─ 状态字段（详细解释每个字段含义）
├─ 特征定义（公式 + 应用场景）
├─ 规则路由架构（优先级 + 流程）

├─ 出场规则详解（6个规则，每个独立章节）
```

3. 排查问题：查看 "已知问题" 章节
4. 配置参数：copy "配置示例" 中的相关段落

**篇幅**：~2500 行，可作为参考手册

## 推荐的使用流程

### Scenario A：初次接触策略体系

1. 先读 **方案二** 的 4 张流程图，理解总体架构（10 分钟）
2. 再读 **方案一** 的 "特征定义" 和 "规则路由架构" 部分（15 分钟）
3. 需要详细了解某条规则时，在 **方案一** 中搜索规则名称（5 分钟/条）

### Scenario B：调试某个规则不生效

1. 在 **方案二** 的流程图中定位该规则（5 分钟）
2. 查看 "对比注记" 中的该规则项，看是否有已知问题（5 分钟）
3. 在 **方案一** 中查看该规则的完整触发条件（10 分钟）
4. 对照代码 (src/polynet_ai/strategy/entry_rules.py 或 exit_rules.py) 检查条件是否满足（15 分钟）

### Scenario C：优化策略或添加新规则

1. 阅读 **方案一** 的 "已知问题与改进空间" 章节，了解当前瓶颈（15 分钟）
2. 查看 **方案二** 的 "建议的文档更新清单"，了解文档缺陷（5 分钟）
3. 根据提名的改进方向，在代码中实现修改
4. 更新两份文档以保持一致

### Scenario D：代码审查或风险评估

1. 通读 **方案二** 以快速掌握现状（20 分钟）
2. 逐个检查 "对比注记" 中标记为 ⚠️ 的项目（30 分钟）
3. 必要时深入 **方案一** 了解详细影响（30 分钟）
4. 生成审查报告，优先级参考 "建议的文档更新清单"

## 后续建议

1. **选择一份作为主要参考**：
   - 如果需要"全面理解"，使用 strategy_spec_enhanced.md
   - 如果需要"快速定位问题"，使用 strategy_flowcharts_and_notes.md
   - 建议两份同时保留，不同场景选用

2. **定期更新文档**：
   - 每次代码迭代后，及时更新相应文档章节
   - 每月进行一次全面核对，检查一致性

3. **建立文档维护流程**：
   - 新增规则 → 同时更新两份文档
   - 修改参数 → 更新配置示例和说明
   - 发现问题 → 补充到 "已知问题" 章节

4. **考虑自动化**：
   - 从代码配置项自动生成文档中的默认值表格
   - 从代码中提取所有规则的优先级自动生成优先级表
